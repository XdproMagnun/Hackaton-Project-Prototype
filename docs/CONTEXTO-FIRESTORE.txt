1. QUE ES EL PROYECTO
------------------------------------------------------------------------------

Ubicarmen es una app web estatica (HTML/CSS/JS clasico, SIN build) que
muestra un mapa de Ciudad del Carmen (Campeche, Mexico) con rutas y paradas
de transporte "Amor X Carmen".

- Datos geograficos: data/routes.json + data/transit.geojson
  (3 rutas, 41 paradas, 43 tramos).
- No hay backend propio: todo es estatico y se sirve con `node server.cjs`
  en http://127.0.0.1:5173
- Firebase se usa solo desde el navegador con el SDK modular por CDN:
  Authentication y Firestore.

5. COMO CONSUME LA APP ESTOS DATOS
------------------------------------------------------------------------------

- data-layer.js (window.UbiData) es la unica puerta a los datos. Lee
  routes, stops, routeSegments, vehicles y meta de Firestore; si algo falla,
  usa data/*.json y emite `ubicarmen:fallback` (banner visible
  "Sin conexion con la nube").

- firebase-auth.js monta el login (correo/contrasena y Google con
  signInWithPopup) y expone window.ubicarmenUser + evento
  `ubicarmen:auth-changed`.

- account.js (window.UbiAccount) sincroniza users/{uid} y
  users/{uid}/favorites/{routeId} con el ID token del SDK.

- Configuracion activa: config.js -> MAP_CONFIG.firebase con
  projectId: 'ubicarmen', useEmulators: false.

------------------------+----------------------------+-----------------------
routeSegments           | {routeId}-{NN}             | routeId, index, name,
                        |                            | accuracy, source,
                        |                            | osmWay,
                        |                            | coordinates:
                        |                            |   [{lng, lat}]
------------------------+----------------------------+-----------------------
vehicles                | {vehicleId}                | routeId, longitude,
                        |                            | latitude, updatedAt,
                        |                            | active, simulated
------------------------+----------------------------+-----------------------
meta                    | version                    | seededAt, source,
                        |                            | projectId, routes,
                        |                            | stops, segments
------------------------+----------------------------+-----------------------
users                   | {uid}                      | name, updatedAt
------------------------+----------------------------+-----------------------
users/{uid}/favorites   | {routeId}                  | routeId, createdAt
                        |                            | (opcional)
------------------------+----------------------------+-----------------------
reports                 | autogenerado               | routeId, stopId, kind,
                        |                            | message, createdAt,
                        |                            | uid, status

Permisos por coleccion:

  routes, stops, routeSegments, vehicles, meta
    lectura: publica            escritura: admin

  users, users/{uid}/favorites
    lectura: solo el dueno      escritura: solo el dueno

  reports
    lectura: solo admin         crear: con sesion iniciada
                                editar/borrar: admin

NOTAS TECNICAS OBLIGATORIAS:

- Geometria fuera de routes: los tramos van en routeSegments porque una ruta
  completa se acerca al limite de 1 MiB por documento.

- Firestore no admite arreglos anidados: por eso las coordenadas se guardan
  como [{lng, lat}] y no como [[lng, lat]]. La app las rehidrata al leer.

- vehicles no lo llena el seed: la app usa simulacion local si la coleccion
  esta vacia. La ingesta real (GPS) requiere escritura de administrador.

7. REGLAS COMPLETAS (pegar en Firestore -> Reglas)
------------------------------------------------------------------------------

rules_version = '2';

// Catalogo publico (rutas, paradas, tramos, meta, vehiculos): lectura abierta,
// escritura solo para administradores con el custom claim admin == true.
// Los datos de cada usuario viven en users/{uid} y solo los ve su dueno.
// Los reportes ciudadanos se pueden crear con sesion, pero no editar ni borrar.

service cloud.firestore {
  match /databases/{database}/documents {

    function signedIn() {
      return request.auth != null;
    }

    function isAdmin() {
      return signedIn() && request.auth.token.admin == true;
    }

    // Sesion anonima (invitado): puede entrar a la app, pero no escribir datos.
    // El catalogo ya es de lectura publica, asi que no necesita mas permisos.
    function isAnonymous() {
      return signedIn() && request.auth.token.firebase.sign_in_provider == 'anonymous';
    }

    function isOwner(uid) {
      return signedIn() && !isAnonymous() && request.auth.uid == uid;
    }

    match /routes/{routeId} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /stops/{stopId} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /routeSegments/{segmentId} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /vehicles/{vehicleId} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /meta/{documentId} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /users/{uid} {
      allow read, write: if isOwner(uid);

      match /favorites/{routeId} {
        allow read, write: if isOwner(uid);
      }
    }

    match /reports/{reportId} {
      // El mensaje y el uid solo son visibles para administradores.
      allow read: if isAdmin();

      // stopId es opcional; si se incluye, debe ser string.
      allow create: if signedIn()
        && !isAnonymous()
        && request.resource.data.keys().hasAll([
          'routeId', 'kind', 'message', 'createdAt', 'uid', 'status'
        ])
        && request.resource.data.keys().hasOnly([
          'routeId', 'stopId', 'kind', 'message', 'createdAt', 'uid', 'status'
        ])
        && request.resource.data.routeId is string
        && (!('stopId' in request.resource.data) || request.resource.data.stopId is string)
        && request.resource.data.uid == request.auth.uid
        && request.resource.data.kind in ['stop', 'incident', 'delay', 'other']
        && request.resource.data.message is string
        && request.resource.data.message.size() > 0
        && request.resource.data.message.size() <= 500
        && request.resource.data.createdAt is string
        && request.resource.data.status == 'open';

      allow update, delete: if isAdmin();
    }

    // Todo lo demas queda cerrado por defecto.
  }
}

- NO crear un service account ni descargar su JSON. No se versiona ninguna

- NO tocar config.js: ya apunta a ubicarmen con useEmulators: false. El
  bloque de emulador es solo para pruebas y se restaura.

  Solo consola + seed.
